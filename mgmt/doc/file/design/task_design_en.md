#### Task Types
- Custom Task: Uses a Crontab expression to set the execution frequency as needed.
- One-Time Task: Executes once and stops, can be re-executed repeatedly.
- Daily Task: Sets tasks to execute on a daily basis.
- Weekly Task: Sets tasks to execute based on weekly maintenance schedules.

#### Task Execution Scope
- Data-based Tasks
- Scenario-based Tasks

#### Task Execution Environment
- Can be associated with a single environment: for functional testing, performance testing, etc.
- Can be associated with multiple environments: for multi-environment testing in the information technology and innovation sector, allowing for execution across multiple environments simultaneously.
- Can be executed without associating with an environment: directly using the environment associated with the scenario.

#### Report Generation
- Single-task execution report: generated automatically after each task execution, viewable via the "Report" action button on each task list row.
- Multi-task merged report:
  1. Check the tasks to merge in the task list (at least 2).
  2. Click the "Generate Report" button at the top, select the associated product (defaults to the products associated with the selected tasks).
  3. After submission, reports are generated asynchronously — one merged report per product, viewable in the report list when done.
- Coverage report: when a task has never been executed, the automation coverage can be statically resolved from the task configuration (scenario / data / API) without requiring execution history.

#### Import Data
- Task data package import:
  1. Click the "Import Data" button at the top of the task list to enter the import page.
  2. Upload the data package (tgz/zip/tar) generated by "One-Click Task Export", containing `task_info.yaml`, `playbook_info.yaml`, and data files.
  3. The system parses and detects conflicts by name (task name / scenario name / data file name).
  4. Choose how to handle: skip conflicting items / overwrite conflicting items / cancel.
  5. Supports importing environment information, assertion information, system parameters, etc. (imported on demand with the task data package).

#### One-Click Task Export
- All information used upstream and downstream of the task is exported as SQL.
- Includes information from forms such as Task/Product/Application/Scenario/Data/Assertion Templates/System Parameters, etc.
- SQL Generation Rules: Skip product and application configurations if they exist; insert if not present, update if present.
- The creator of the data is uniformly set to the information of the person performing the export operation, and the product or associated product belongs to the information of the first product in the exported task.
- Data file package: the task's data files, task info (task_info.yaml), and scenario info (playbook_info.yaml) are packaged into a tgz data package, usable for "Import Data", "LLM Training", "Data Upgrade", etc.
- The data file package supports exporting environment information and i18n corpora on demand.

#### LLM Training
- Data source: the tgz data package generated by "One-Click Task Export", provided for LLM training.
- Debug execution: after training, the LLM can call the CLI HTTP interfaces to debug
  - /cli/login        obtain a TOKEN (username/password)
  - /cli/dataRun      run data (upload a data file)
  - /cli/playbookRun  run scenarios (upload scenario files)

#### Crontab Expression
```
* * * * *
- - - - -
| | | | |
| | | | +-------------- Day of the week (0 - 6) (Sunday is 0)
| | | +---------------- Month (1 - 12)
| | +------------------ Day of the month (1 - 31)
| +---------------------- Hour (0 - 23)
+------------------------- Minute (0 - 59)
```
This Crontab expression allows you to specify when a task should be executed based on minutes, hours, days of the month, months, and days of the week.
