#### Run Mode
- CLI (command line) run mode is Data4Test's offline run form, complementing the Web form (GoAdmin + Gin).
- Uses SQLite local storage without MySQL, enabling offline execution of data/scenarios and report viewing.
- Task packages are generated by the web-side "One-Click Task Export" and contain task_info.yaml, playbook_info.yaml, data files, env_config.yaml, upload/, and i18n corpus.

#### Getting Started
- Running `./data4test run|report|help` enters the CLI branch without connecting to MySQL or starting GoAdmin.
- On first run, a local SQLite database cli.db is auto-created with tables (10 core tables).

#### Subcommands
- run: execute tasks in the task package.
- report: list recent reports / export report HTML / regenerate multi-task reports.
- help: show help.

#### run Command
- Usage: `./data4test run [options]`
- Options:
  - `--task TaskA,TaskB`    execute only the specified tasks (default: all)
  - `--pkg task/xxx.tgz`    explicitly specify the task package (default: the latest modified package under task/)
  - `--reconfig`            re-copy the original env_config.yaml from the package, overwriting local
  - `--param Name=value`    inject placeholder values from the command line, comma-separated multiple, repeatable, e.g. `--param A=1,B=2`
  - `--language en`         language for this run, overriding the config.json default
  - `--mock`                start the local Mock service in the background (auto-starts when a /mock/ reference is detected)
- Execution flow: select package → extract env_config.yaml/upload/i18n → seed local env_config.yaml (first run or --reconfig) → load config → inject --param → fill remaining placeholders (interactive) → required validation → import via web logic → sync env_config.yaml → copy upload → start Mock as needed → execute tasks in order → regenerate multi-task report.
- Exit codes: 0 all pass, 3 has failures, 1 execution error.

#### report Command
- `./data4test report`                      list recent reports
- `./data4test report <ID>`                 export a report as standalone HTML and open it in the browser
- `./data4test report --multi --task 1,2`   regenerate a multi-task report from report IDs
- Option: `--language en`   language for viewing/generating reports.

#### Placeholder Injection
- If the config file (env_config.yaml) contains {NameXXX} placeholders, they are detected and prompted before execution.
- Use `--param Name=value` to inject directly from the command line (comma-separated multiple, repeatable); after injection values are auto-written back, so next time no filling is needed.
- Pressing Enter to skip keeps the value unchanged and continues execution; filled values are auto-written back to the config file.
- You can manually edit env_config.yaml to replace {NameXXX} placeholders with actual values.

#### env_config.yaml Structure
- product: product environment (name / ip / protocol / auth / threading / apps / private_parameter, etc.)
- app: per-application environment config (ip / prepath / auth, etc.); app-level ip / auth inherit product when empty.
- sys_parameter: system parameters (multi-language, feature data, cascading data, etc.)
- assert_template: assertion value templates.
- mock: local Mock service config (enable / port / base_url).

#### Authentication
- CLI offline execution directly uses the auth info in env_config.yaml.
- CLI HTTP interfaces (/cli/login, /cli/dataRun, /cli/playbookRun) are also provided for external callers to obtain a TOKEN and execute data/scenarios.
