## 1. 背景与问题

平台现有的「定时任务」（`schedule`）支持把多个数据文件或场景关联到一个任务，并按 cron 定时执行、生成任务级报告。但一个完整的回归或版本验证通常需要**多个任务组合执行**，当前存在以下问题：

1. 多个任务只能逐个手动运行，无法统一触发；
2. 任务之间存在先后依赖时（例如先登录冒烟、再执行主流程），无法保证顺序；
3. 没有一个"整体视角"的结果报告，需要逐个任务翻看报告。

## 2. 目标与价值

- 支持**基于已有任务组装任务编排**，按顺序串行执行；
- 支持**编排级统一触发**：页面「立即执行」；
- 提供**编排级汇总报告**，可下钻到任务原有报告；
- 支持任务编排及其完整依赖的**导入/导出**，用于跨环境迁移和配置复用；
- 不改变任务本身的定义与执行逻辑，存量功能零回归。

## 3. 用户与角色

| 角色 | 主要诉求 |
|---|---|
| 测试负责人 | 创建编排、编排步骤、配置编排级产品、查看整体结果 |
| 测试执行人员 | 立即执行编排、查看编排报告并定位失败任务 |
| 系统管理员 | 配置菜单与角色权限 |

## 4. 名词定义

| 名词 | 定义 |
|---|---|
| 任务编排 | 由若干任务按顺序组成的执行单元 |
| 编排步骤 | `task_list` 中的一行，即一个任务名称；不复制任务配置 |
| 编排报告 | 每轮执行生成的一条汇总报告，`dashboard.report_type=orchestration` |
| 步骤结果 | 本轮中某个任务的执行结果，关联该任务的任务报告 |
| 编排导出包 | 包含编排、步骤任务及任务依赖的场景、数据文件、产品配置和附件的可移植归档包 |

## 5. 需求范围

### 5.1 本期范围

- 任务编排的增删改查、复制、列表管理；
- 编排任务编排（`task_list` 存任务名称，行序即步骤顺序）；
- **串行执行**，执行方式固定为串行；
- **页面「立即执行」**；
- **失败继续**：普通失败继续执行后续步骤；`scene` / `data` 步骤 401 鉴权失败时停止后续步骤；
- **编排级产品配置**，配置后覆盖步骤任务的产品，未配置时沿用任务产品；
- **编排级汇总报告并入「结果报告列表」**（报告类型新增"任务编排"），支持下钻任务报告；
- 任务编排及完整依赖的导出，以及“检查 → 冲突处理 → 确认”的两阶段导入；
- 定时任务列表「加入编排」快捷入口；
- 菜单、权限、i18n。

### 5.2 不在本期范围

- **并行执行**（并发上限、排队、并发失败处理）；
- **cron / 每天 / 每周定时触发**及重启恢复；
- **「运行」与「停止」按钮**，包括批量停止；
- **CLI / CI 接口**；
- **编排执行前的统一产品鉴权刷新**；
- 编排中直接引用数据文件或场景（仍通过任务间接引用）；
- 步骤级产品覆盖、步骤级重试、步骤级超时；
- 邮件/IM 通知、审批流。

## 6. 业务场景

**场景一：版本回归（串行 + 失败继续）**

测试负责人把"登录冒烟""订单主流程""报表回归"三个任务按顺序组装成"版本回归编排"，点击「立即执行」。若"订单主流程"存在用例失败，"报表回归"仍会继续执行；全部结束后在编排报告里按步骤查看结果，并点进失败任务的任务报告定位问题。

**场景二：鉴权失效中止**

编排第 1 步是登录冒烟（`scene` 任务），执行时被测系统返回 401。系统判定为鉴权失败，停止后续步骤并标记为"跳过"，编排报告明确展示失败原因，避免后续步骤在无效会话下继续跑。`data` 任务返回 401 时同样停止。

**场景三：跨环境迁移**

测试负责人从源环境导出任务编排，导出包包含编排、步骤引用的定时任务及其场景、数据文件、产品配置和附件。在目标环境上传后，系统先检查同名编排及依赖冲突并展示差异；负责人选择跳过或覆盖后确认导入。若任一步骤任务无法导入或映射，则该编排整体不落库，并明确列出缺失任务。

## 7. 功能需求

### 7.1 任务编排列表（FR-01）

- 菜单位置：任务 → 任务编排；路由 `/admin/info/task_orchestration`。
- 列表字段：编排名称、步骤数、关联产品（推导）、状态、上次执行时间、创建人、创建时间。
- 筛选：编排名称（模糊）、状态、创建人（模糊）、创建时间（范围）。
- 排序：上次执行时间、创建时间。
- 批量操作：**批量立即执行、批量复制、批量导出**。
- 行操作：立即执行、复制、报告、导出、编辑、删除。
- 页面顶部提供「导入」入口，进入上传检查、冲突处理与确认导入流程。
- 列表交互、状态展示风格与定时任务一致。

### 7.2 新建 / 编辑编排（FR-02）

必填与校验：

- 编排名称必填且唯一；
- 关联任务至少 1 个，任务必须存在且未删除，不允许重复；
- 校验失败时整体不保存。

字段：

| 字段 | 说明 |
|---|---|
| 编排名称 | 文本 |
| 关联任务 | 多行文本，每行一个任务名称，行序即步骤顺序 |
| 产品配置 | 多选，选填；**配置后覆盖所有步骤任务的产品**，为空时沿用各任务自身产品 |
| 备注 | 选填 |

规则：

- 本期表单不展示编排模式、调度配置、执行方式、失败策略；
- 编排执行中禁止修改关联任务（避免配置漂移）；
- 保存为单条写入（单语句原子），校验在写入前完成，失败时不落库。

### 7.3 步骤编排（FR-03）

- 步骤引用已有定时任务，不复制任务配置；任务修改后编排下次执行生效。
- 步骤按行序执行，行序即步骤顺序。
- 同一任务在同一编排中只能出现一次。
- 详情页有序展示步骤：序号、任务名称、任务类型、关联产品。
- 任务被删除或改名时，详情页标记该步骤不可用；执行前置校验失败。
- 后续增强（P1）：独立编排页、拖拽排序、步骤启用/禁用。

### 7.4 编排复制（FR-04）

- 复制编排基本信息、关联任务与产品配置；
- 新编排名称追加"_副本"，状态重置为未执行。

### 7.5 删除编排（FR-05）

- 软删除；
- 编排存在执行中的记录时禁止删除；
- 删除时改写编排名称（追加删除时间戳），保证同名编排可重建；
- 删除编排不影响被引用的任务。

### 7.6 立即执行（FR-06）

- 点击后立即执行一轮，不涉及任何调度状态；
- 触发方式固定记录为 manual；
- 编排正在执行时不允许重复触发，提示"编排正在执行"；
- 执行开始后不提供停止/中断，需等待本轮结束。

### 7.7 串行执行（FR-07）

- 按关联任务的行序逐个执行，上一个步骤结束后执行下一个；
- 步骤之间不并发；
- 每一步产生独立的步骤结果，并生成对应任务的任务报告用于下钻。

### 7.8 失败处理（FR-08）

| 情形 | 处理 |
|---|---|
| 步骤成功 | 继续下一步骤 |
| 普通失败（用例失败、非 401 接口错误、脚本失败） | 记录失败，**继续**执行后续步骤 |
| 步骤返回 401 鉴权失败（`scene` / `data`） | 记录失败，**后续步骤标记跳过并停止** |

- 401 判定沿用系统现有实现：用 `error.auth_fail_prefix` 文案前缀匹配（与定时任务 `scene` 路径一致）；`data` 路径需修正原始错误被 `test <result>` 覆盖的问题，使二者判定方式统一；
- 不提供失败策略配置项，行为固定如上；
- 最终以编排报告汇总结果为准。

### 7.9 编排报告（FR-09）

- **报告并入「结果报告列表」**：报告类型新增枚举"任务编排"，每轮执行结束后自动生成一条编排报告并出现在列表中；
- 报告类型展示与筛选支持"任务编排"；列表可按报告名称、产品、创建人筛选（现有报告列表不提供时间筛选，本期不新增）；
- 页面路由：复用 `/admin/report_dashboard?id=<dashboard_id>`；编排列表「报告」跳转该编排最近一次执行；
- 内容：
  1. 概览：编排名称、触发方式、起止时间、总耗时、步骤总数、成功/失败/跳过数、执行率；
  2. 步骤明细：序号、任务名称、状态、起止时间、耗时、通过/失败用例数、错误信息、"查看任务报告"链接；
  3. 产品维度汇总：产品、总数、通过、失败、通过率（按本轮实际使用的产品聚合）；
  4. 历史执行选择：最近 20 次执行记录切换；
  5. 趋势图（P1）。
- 离线导出：本期只要求**离线渲染能力就绪**（`pages/report_export.go` 支持 `report_type=orchestration`）；CLI 本期无编排执行入口，报告不会进入 CLI 本地库，端到端导出留待后续版本。

### 7.10 任务列表「加入编排」（FR-10）

- 定时任务列表增加行操作/批量操作「加入编排」；
- 弹窗选择目标任务编排，将选中任务按顺序追加到编排末尾；
- 已存在于该编排的任务自动跳过并提示；
- 该入口不改变编排的任何配置。

### 7.11 权限（FR-11）

- 新增菜单与页面权限：查询、新建、编辑、删除、导出；
- 编排立即执行/复制等操作随页面权限；
- 编排报告页、导入页权限；
- 在「角色管理」中分配给对应角色；
- 菜单与权限种子以 `INSERT` 形式追加到 `mgmt/sql/update.sql`（不修改已定型的 `init_all_*.sql`）；权限项参照 `test_case` 的写法，菜单 id、权限 id 需避开现有最大值。

### 7.12 多语种（FR-12）

- 菜单中英文：任务编排 / Task Orchestration；
- 页面字段、状态、提示、错误信息均通过 `biz.T()` 输出；
- 新增 key 同步写入 `zh-CN.json`、`en-US.json` 与菜单翻译文件。

### 7.13 执行记录与互斥（FR-13）

- 每次执行产生一条编排报告与 N 条任务报告，不新建执行记录表；
- 同一编排同一时间只允许一轮执行：页面提示"编排正在执行"；
- 服务重启时，将遗留的 `running` 编排状态重置为已结束，避免状态悬挂。

### 7.14 编排级产品覆盖（FR-14）

- 编排表单新增「产品配置」，支持选择一个或多个产品（存 `product_list`，逗号分隔）；
- **优先级：编排级 > 任务级**。编排配置了产品时，本轮所有步骤按编排产品执行，任务报告中的关联产品也同步为编排产品；
- 编排未配置产品时，沿用各步骤任务自身的 `product_list`，保持原有行为；
- 编排列表「关联产品」展示编排级产品；编排未配置时展示步骤任务的产品并集；
- 本期编排执行前**不做**统一产品鉴权刷新；
- 编排配置的产品必须存在且去重；**`data` 类型步骤只使用第一个产品**（现有 data 执行链路按单产品精确匹配取环境配置，多产品仅对 `scene` 步骤完整生效）。

### 7.15 编排导出（FR-15）

- 编排列表支持单条导出与批量导出；
- 导出内容为可重新导入的单一 zip 归档包，结构为 `orchestration_info.yaml`（编排清单）+ `products_info.yaml`（产品配置）+ `bundle/`（复用现有任务导出生成的任务/场景/数据/附件依赖包），包含：
  1. 编排基本信息、关联任务、编排级产品及步骤顺序；
  2. 步骤引用的完整定时任务定义；
  3. 任务依赖的场景、数据文件、产品配置、环境配置、断言模板、系统参数及上传附件；
- 导出前校验依赖闭包：**任务、场景、数据文件**缺失时终止导出并返回缺失项；**产品、环境配置**缺失只记录告警、不阻断导出；
- 包内使用稳定业务标识（编排名、任务名、场景名、数据文件名）表达关联，不依赖源环境数据库 ID；
- 导出结果应确定性排序，便于版本比较与重复导入验证。

### 7.16 编排导入（FR-16）

- 采用“上传检查 → 冲突处理 → 确认导入”的两阶段流程，支持 `skip`、`overwrite`、`cancel`；
- 检查阶段展示编排、任务、场景、数据、产品等对象的同名冲突，以及每个编排的任务映射（已存在 / 将导入 / 缺失）和缺失项；存在缺失任务时检查阶段直接阻断；
- 确认阶段复用现有任务导入实现先落依赖，再按任务名映射逐条创建/跳过/覆盖编排；**不做跨编排事务**，单个编排失败只回滚该条，不影响其他完整编排；
- `skip` 表示复用目标环境同名对象，仍须保留编排与该对象的关联；`overwrite` 表示更新同名对象；`cancel` 不落库；
- 任一步骤任务无法导入或映射时，该编排整体不落库，并明确返回缺失任务；
- 同一导入包内多个编排互相独立：单个编排失败不影响其他依赖完整的编排，但共享依赖的写入必须保持一致；
- 导入为异步耗时操作，确认接口立即返回导入任务标识，页面可查询最终结果（现有任务导入为 fire-and-forget、无状态接口，此为**新增能力**，需持久化导入任务状态并支持页面轮询）；
- 导入不得执行包内 SQL 或脚本；归档解包需防止路径穿越，附件和数据文件仅写入平台规定目录。

## 8. 状态定义

### 8.1 编排状态（`orchestration_status`）

| 状态 | 含义 |
|---|---|
| not_started | 未执行（新建/复制） |
| running | 正在执行 |
| finished | 本轮执行结束（无论成功或失败，结果以编排报告为准） |
| stopped | 预留，本期不使用 |

### 8.2 步骤状态（编排报告内）

`success` / `fail` / `skipped`

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 兼容性 | 不改变现有任务、报告、cron 行为；未使用编排的环境零影响 |
| 并发安全 | 同编排互斥执行；步骤串行执行，无并发写竞争 |
| 性能 | 编排报告聚合为纯查询，单次聚合 ≤ 2 秒（100 步以内） |
| 可靠性 | 编排报告完整落库；服务重启后不残留 running 状态；异常不导致进程退出 |
| 可观测性 | 关键节点写 `biz.Logger`；步骤错误信息落库并展示 |
| 安全 | 页面操作受 RBAC 控制；导入包限制类型与大小，防止路径穿越，不执行包内 SQL/脚本；编排不额外存储敏感信息 |
| 数据保留 | 编排报告随执行次数增长，本期不做自动清理 |
| 可用性 | 列表/表单交互与定时任务一致，降低学习成本 |

## 10. 验收标准

| 编号 | 验收项 | 预期结果 |
|---|---|---|
| AC-01 | 新建编排（3 个步骤） | 列表展示步骤数 3，详情按顺序展示任务 |
| AC-02 | 编排名重复 / 任务不存在 / 任务重复 / 无步骤 | 保存失败并给出明确提示 |
| AC-03 | 串行执行 | 按行序逐个执行，步骤之间不并发 |
| AC-04 | 普通失败继续 | 第 2 步失败，第 3 步仍执行，报告显示 1 失败 2 成功 |
| AC-05 | scene 步骤 401 停止 | 第 2 步 401，第 3 步为跳过，报告可见失败原因 |
| AC-06 | data 步骤 401 | 同样触发停止，且错误原文未被覆盖 |
| AC-07 | 立即执行 | 生成 1 条编排报告 + N 条任务报告，不产生调度状态 |
| AC-08 | 同一编排并发触发两次 | 仅一轮执行，另一次提示"编排正在执行" |
| AC-09 | 编排级产品覆盖 | 编排配置产品 A、步骤任务配置产品 B，执行请求发往 A，任务报告关联产品为 A |
| AC-10 | 编排产品回退 | 编排未配置产品时，步骤按各任务自身产品执行 |
| AC-11 | data 步骤单产品 | 编排配置多个产品时，data 步骤只使用第一个产品且能取到环境配置 |
| AC-12 | 任务状态不受影响 | 编排执行后 `schedule.task_status` 保持不变 |
| AC-13 | 编排报告下钻 | 点击步骤可进入对应任务本次报告 |
| AC-14 | 报告统一列表 | 编排执行完成后，「结果报告列表」出现类型为"任务编排"的报告，可筛选并打开下钻 |
| AC-15 | 离线渲染能力 | 构造一条 `report_type=orchestration` 报告，离线渲染可正常输出 HTML（CLI 本地库入口留待后续） |
| AC-16 | 任务列表「加入编排」 | 选中任务追加到编排末尾，重复任务被跳过 |
| AC-17 | 权限与 i18n | 无权限角色不可访问；中英文切换正常 |
| AC-18 | 同名编排重建 | 删除编排后可用同一名称重新创建成功 |
| AC-19 | 存量回归 | 既有任务执行、报告、cron 行为不变 |
| AC-20 | 单条/批量导出 | 生成一个编排归档包，包含所选编排、步骤任务及完整依赖，且关联不依赖源环境数据库 ID |
| AC-21 | 导入检查 | 上传归档包后展示编排、任务、场景、数据、产品等对象的新增、冲突、缺失及映射结果，不直接落库 |
| AC-22 | 跳过冲突导入 | 复用目标环境同名对象并保留全部关联，完整编排成功落库 |
| AC-23 | 覆盖冲突导入 | 同名对象按包内容更新，步骤正确映射到目标环境任务 ID |
| AC-24 | 步骤任务缺失 | 任一步骤任务无法导入或映射时，该编排整体不落库，并返回缺失任务明细 |
| AC-25 | 导入包安全 | 路径穿越、超限归档被拒绝且不污染目标目录；**本期不做非法文件类型限制**（与现有任务导入一致，未知扩展名按 `file_type=99` 处理） |

## 11. 边界与限制

1. 执行开始后不能中断，只能等待本轮结束；
2. 本期仅串行执行，无并行、无 cron 定时、无 CLI 触发；
3. 编排配置了产品时，所有步骤统一使用编排产品，步骤任务自身的产品配置在本轮被覆盖；其中 `data` 类型步骤只使用第一个产品；
4. `scene` 与 `data` 类型步骤均参与 401 判定，判定方式沿用系统现有文案前缀实现；
5. 编排引用的任务被删除或改名后，编排执行前置校验失败，整轮不执行；
6. 编排执行中不允许修改关联任务；
7. 编排执行记录不做自动清理（后续增量）；
8. 编排名称唯一索引叠加软删除，删除时需改写名称（追加删除时间戳），否则同名编排无法重建；
9. 导入导出复用现有任务导出/导入能力：依赖包选择依据"归档内是否含 `task_info.yaml`"，不依赖文件名前缀；
10. 归档仅限制路径穿越、文件数与解压总大小，未做扩展名白名单（平台本身需导入脚本文件）；
11. 导入页及 check/confirm/status/labels 接口校验登录与导入页权限（309）；立即执行/复制按编辑权限、导出按导出权限校验；
12. CLI 本期无编排执行入口，编排报告不会进入 CLI 本地库；
13. 定时任务导入接口属于历史功能，本期不做鉴权与路径校验改造；相关加固只在任务编排导入侧实施。

## 12. 依赖与风险

| 风险/依赖 | 说明 | 应对 |
|---|---|---|
| 依赖任务执行函数改造 | 需要抽取 `RunTaskOnce` 返回执行结果与任务报告 ID，并支持产品覆盖与状态隔离 | 保留 `RunOnceTask` 兼容包装，减小回归风险 |
| 产品覆盖一致性 | 编排产品覆盖任务产品后，执行与任务报告需使用同一套有效产品 | 统一由 `effectiveProductList` 计算，执行与报告共用 |
| 401 判定方式 | 状态码只存在于错误文案中，无 typed error | 沿用现有 `error.auth_fail_prefix` 前缀判断，scene/data 统一；后续可引入 typed error 增强 |
| data 链路覆盖错误 | `data_run.go` 会用 `test <result>` 覆盖错误原文，导致 401 丢失 | 修正为仅在 `err == nil` 时写 `test %s`，并行分支保留 `err1` |
| 执行错误被覆盖 | `RunOnceTask` 末尾用 `schedule` 更新的 error 覆盖执行错误 | 抽取 `RunTaskOnce` 时用独立变量保存并返回执行错误 |
| 报告关联约定 | 编排报告复用 `related_task_ids` 存 `orch:<id>:<tag>` | 所有按任务 id 解析该字段的代码需按 `report_type` 过滤 |
| 报告渲染多链路 | 编排报告除 Web 渲染外，还需覆盖离线渲染与 GoAdmin 详情页；CLI 本期无编排入口 | 在 `pages/report_export.go` 补 `case "orchestration"`（能力就绪），详情页链接按报告类型分流；CLI 端到端留待后续 |
| 导出依赖闭包不完整 | 复用现有 `ExportSchedule`，其自身校验存在缺口（如纯数据任务可能不生成数据包） | 导出前校验任务存在；导入端按归档内是否含 `task_info.yaml` 选包；后续如需严格闭包再增强 |
| 同名对象关联丢失 | 现有任务导入按冲突项过滤关联，可能导致跳过/覆盖后任务与场景解除关联 | 检查阶段生成显式名称映射，确认阶段先落依赖再重建全部关联 |
| 导入包安全 | 非法归档可能造成路径穿越、资源耗尽或文件污染 | 限制路径穿越、文件数与解压总大小，解压到临时目录；脚本类文件属合法内容，不做扩展名白名单 |
| 导入无跨编排事务 | 单个编排失败只回滚该条，任务/场景等依赖由现有导入实现落库，无法整体回滚 | 失败编排不落库并返回明细，其他编排继续导入；已落库的依赖保留 |

## 13. 已确认口径

2026-10-23 首次确认，2026-11-05 按新范围重定（含概念统一为"任务编排"）：

1. **只新增 `task_orchestration` 一张表**：任务编排存 `task_list`（每行一个任务名），不建步骤表与执行记录表。
2. **执行记录复用定时任务模型**：每步一条任务报告 + 每轮一条编排报告（`report_type=orchestration`），`dashboard` 不新增列。
3. **仅串行、仅立即执行**：并行执行、cron 定时、运行/停止按钮、CLI/CI 均不纳入本期；调度相关字段在表中预留。
4. **失败继续 + 401 停止**：不保留失败策略字段；普通失败继续，`scene` / `data` 步骤 401 鉴权失败时停止后续步骤，判定沿用系统现有实现。
5. **不需要统一鉴权刷新**：编排执行前不做产品鉴权刷新。
6. **编排级产品优先**：编排未配置时回退任务自身产品；`data` 步骤只取首个产品。
7. **同名编排可重建**：删除时改写 `orchestration_name` 为 `<原名>_deleted_<时间戳>`。
8. **编排导入/导出纳入本期**：导出编排、步骤任务及完整依赖；导入两阶段检查，支持跳过/覆盖冲突；步骤任务无法映射时该编排整体失败。
