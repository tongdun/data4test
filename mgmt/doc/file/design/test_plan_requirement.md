## 1. 背景与问题

平台现有的「定时任务」（`schedule`）支持把多个数据文件或场景关联到一个任务，并按 cron 定时执行、生成任务级报告。但一个完整的回归或版本验证通常需要**多个任务组合执行**，当前存在以下问题：

1. 多个任务只能分别配置 cron 或逐个手动运行，无法统一触发；
2. 任务之间存在先后依赖时（例如先登录冒烟、再执行主流程），无法保证顺序；
3. 互不依赖的任务无法并发执行，回归总耗时较长；
4. 没有一个"整体视角"的结果报告，需要逐个任务翻看报告；
5. CI/CD 流水线无法用一次调用触发一组任务。

## 2. 目标与价值

- 支持**基于已有任务组装测试计划**，按顺序或并发执行；
- 支持**计划级统一触发**：手动、cron 定时、CLI/CI；
- 支持**计划级失败策略**：失败即停或失败继续；
- 提供**计划级汇总报告**，可下钻到任务原有报告；
- 支持测试计划及其完整依赖的**导入/导出**，用于跨环境迁移和配置复用；
- 不改变任务本身的定义与执行逻辑，存量功能零回归。

## 3. 用户与角色

| 角色 | 主要诉求 |
|---|---|
| 测试负责人 | 创建计划、编排步骤、配置调度与失败策略、查看整体结果 |
| 测试执行人员 | 立即执行计划、停止计划、查看计划报告并定位失败任务 |
| 系统管理员 | 配置菜单与角色权限、调整并发上限等系统参数 |
| CI/CD 系统 | 通过 CLI 接口触发计划并轮询执行结果 |

## 4. 名词定义

| 名词 | 定义 |
|---|---|
| 测试计划 | 由若干任务按顺序组成的执行单元，带调度配置与执行策略 |
| 计划步骤 | 计划中的一个任务引用 + 顺序号；不复制任务配置 |
| 计划执行记录 | 每次触发产生的一条记录，包含本轮状态、耗时、报告数据 |
| 步骤执行记录 | 本轮中某个任务的执行结果，关联任务报告 |
| 计划模式 | cron / once / day / week，语义同定时任务 |
| 执行方式 | 串行（serial）/ 并发（concurrent） |
| 失败策略 | 失败即停（stop）/ 失败继续（continue） |
| 计划导出包 | 包含计划、步骤任务及任务依赖的场景、数据文件、产品配置和附件的可移植归档包 |

## 5. 需求范围

### 5.1 本期范围

- 测试计划的增删改查、复制、列表管理；
- 测试计划及完整依赖的导出，以及“检查 → 冲突处理 → 确认”的两阶段导入；
- 计划步骤编排（引用已有定时任务，支持顺序）；
- **计划级产品配置**，配置后覆盖步骤任务的产品，未配置时沿用任务产品；
- 串行/并发执行，计划级失败策略；
- 手动执行、立即执行、cron 定时触发、CLI/CI 触发；
- **计划级汇总报告并入「结果报告列表」**（报告类型新增"计划"），支持下钻任务报告；
- 定时任务列表「加入计划」快捷入口；
- 菜单、权限、i18n。

### 5.2 不在本期范围

- 计划中直接引用数据文件或场景（仍通过任务间接引用）；
- 步骤级产品覆盖、步骤级重试、步骤级超时；
- 邮件/IM 通知、审批流；
- 执行中任务的中断/杀进程（现有任务能力不支持）。

## 6. 业务场景

**场景一：版本回归（串行 + 失败即停 + 定时触发）**

测试负责人把"登录冒烟""订单主流程""报表回归"三个任务按顺序组装成"版本回归计划"，设置串行、失败即停、每天 02:00 执行。次日查看计划报告，若"订单主流程"失败，则"报表回归"显示为跳过，可直接点进失败任务的报告定位问题。

**场景二：发布后冒烟（并发 + CLI 触发）**

三条互不依赖的冒烟任务组装为"发布冒烟计划"，设置并发、失败继续。CI 流水线在发布完成后调用 `/cli/planRun` 触发，轮询 `/cli/planRunStatus` 获取结果，有失败则阻断发布。

**场景三：临时验证（手动立即执行）**

计划平时由 cron 每天执行。测试人员临时修改某任务后，希望在当前时间立即验证一次，触发后不改变原有的 cron 调度状态。

**场景四：结果下钻**

从计划报告看到某步骤失败，点击"查看任务报告"进入该任务本次执行的任务级报告，查看失败用例明细。

**场景五：跨环境迁移**

测试负责人从源环境导出测试计划，导出包包含计划、步骤引用的定时任务及其场景、数据文件、产品配置和附件。在目标环境上传后，系统先检查同名计划及依赖冲突并展示差异；负责人选择跳过或覆盖后确认导入。若任一步骤任务无法导入或映射，则该计划整体不落库，并明确列出缺失任务。

## 7. 功能需求

### 7.1 测试计划列表（FR-01）

- 菜单位置：任务 → 测试计划；路由 `/admin/info/test_plan`。
- 列表字段：计划名称、计划模式、执行方式、失败策略、步骤数、关联产品（推导）、状态、上次执行时间、下次执行时间、创建人、创建时间。
- 筛选：计划名称（模糊）、计划模式、状态、执行方式、失败策略、创建人（模糊）、创建时间（范围）。
- 排序：上次执行时间、下次执行时间、创建时间。
- 批量操作：批量运行、批量停止、批量复制、批量导出。
- 行操作：运行、立即执行、停止、复制、报告、导出、编辑、删除。
- 页面顶部提供「导入」入口，进入上传检查、冲突处理与确认导入流程。
- 列表交互、状态展示风格与定时任务一致。

### 7.2 新建 / 编辑计划（FR-02）

必填与校验：

- 计划名称必填且唯一；
- 计划模式必填；cron 模式下 cron 表达式必填且合法；
- 关联任务至少 1 个，任务必须存在且未删除，不允许重复；
- 执行方式、失败策略必填，默认"串行""失败即停"。

字段：

| 字段 | 说明 |
|---|---|
| 计划名称 | 文本 |
| 计划模式 | cron / once / day / week，联动显示调度字段 |
| cron / 每周 / 每天时间 | 与定时任务一致 |
| 执行方式 | 串行 / 并发 |
| 失败策略 | 失败即停 / 失败继续 |
| 关联任务 | 每行一个任务名称，行序即步骤顺序 |
| 产品配置 | 多选，选填；**配置后覆盖所有步骤任务的产品**，为空时沿用各任务自身产品 |
| 备注 | 选填 |

规则：

- 计划执行中禁止修改步骤（避免配置漂移）；
- 保存步骤采用事务，失败时整体回滚。

### 7.3 步骤编排（FR-03）

- 步骤引用已有定时任务，不复制任务配置；任务修改后计划下次执行生效。
- 步骤按顺序号执行，顺序号从 1 递增。
- 同一任务在同一计划中只能出现一次。
- 详情页有序展示步骤：序号、任务名称、任务类型、关联产品。
- 任务被删除时，详情页标记该步骤不可用；执行前置校验失败。
- 后续增强（P1）：独立编排页、拖拽排序、步骤启用/禁用。

### 7.4 计划复制（FR-04）

- 复制计划基本信息与全部步骤；
- 新计划名称追加"_副本"，状态重置为未开始；
- 复制后的计划不继承 cron 注册状态，需手动运行后生效。

### 7.5 删除计划（FR-05）

- 软删除；
- 计划存在执行中的记录时禁止删除，需先停止；
- 删除计划不影响被引用的任务。

### 7.6 运行（FR-06）

与定时任务行为一致：

- `once` 计划：立即执行一次，执行结束后计划状态为"已完成"；
- `cron/day/week` 计划：注册调度并将计划状态置为"运行中"；
- 计划已在运行中（调度已启用）时重复点击运行给出提示。

### 7.7 立即执行（FR-07）

- 不改变计划原有的调度状态与 `last_at/next_at` 调度计算；
- 立即产生一条 `trigger_type=manual` 的执行记录；
- 计划正在执行时不允许重复触发。

### 7.8 停止（FR-08）

- 取消 cron 调度（once 计划无调度）；
- 计划状态置为"已停止"；
- 若计划正在执行：请求停止本轮，**未开始的步骤标记为跳过**；已开始的任务继续执行到结束；
- 再次运行可重新注册调度或执行。

### 7.9 串行执行（FR-09）

- 按步骤顺序逐个执行，上一个步骤结束（无论成功失败）后执行下一个；
- 步骤之间不并发；
- 每一步产生独立的步骤执行记录与任务报告。

### 7.10 并发执行（FR-10）

- 计划内步骤并发执行，并发上限由系统参数 `planMaxConcurrency` 控制（默认 5）；
- 超出的步骤排队等待；
- 每一步产生独立的步骤执行记录与任务报告；
- 页面需提示：并发仅建议用于相互独立的任务，共享产品环境时可能相互影响。

### 7.11 失败策略（FR-11）

| 执行方式 | 失败即停 | 失败继续 |
|---|---|---|
| 串行 | 当前步骤失败后，剩余步骤标记跳过，计划失败 | 继续执行剩余步骤，最终计划状态为失败（存在失败） |
| 并发 | 已启动步骤继续执行；排队中未启动的步骤取消并标记跳过 | 所有步骤均执行，最终计划失败 |

### 7.12 定时触发（FR-12）

- 支持 cron / 每天 / 每周三种调度模式，语义与定时任务一致；
- 计划列表展示上次/下次执行时间，每次执行后更新；
- 服务重启后，运行中（`plan_status=running`）的计划自动恢复调度；
- 计划执行时间到达时若上一轮仍在执行，本轮跳过并记录日志。

### 7.13 CLI / CI 触发（FR-13）

复用现有 CLI 认证（`/cli/login` 获取 JWT）：

| 接口 | 方法 | 说明 |
|---|---|---|
| `/cli/planRun` | POST | 按 `plan_name` 或 `plan_id` 触发；默认异步，返回 `run_id`；支持 `wait=true` 同步等待 |
| `/cli/planRunStatus` | POST | 按 `run_id` 查询状态、步骤结果、报告地址 |
| `/cli/planStop` | POST | 按 `plan_id` 或 `run_id` 停止计划/本轮执行 |

约定：

- 响应统一 `{code, msg, data}`；
- 计划已在执行时返回错误码与可读提示；
- CLI 触发不改变计划的 cron 调度状态。

### 7.14 计划报告（FR-14）

- **报告并入「结果报告列表」**：报告类型新增枚举"计划"，计划每轮执行完成后自动生成一条计划报告并出现在列表中；
- 报告类型展示与筛选支持"计划"；列表可按报告名称、产品、创建人筛选（现有报告列表不提供时间筛选，本期不新增，避免超出既有能力）；
- 页面路由：复用 `/admin/report_dashboard?id=<dashboard_id>`；计划列表「报告」跳转该计划最近一次执行；
- 内容：
  1. 概览：计划名称、触发方式、执行方式、失败策略、起止时间、总耗时、步骤总数、成功/失败/跳过数、执行率；
  2. 步骤明细：序号、任务名称、状态、起止时间、耗时、通过/失败用例数、错误信息、"查看任务报告"链接；
  3. 产品维度汇总：产品、总数、通过、失败、通过率（按本轮实际使用的产品聚合）；
  4. 历史执行选择：最近 20 次执行记录切换；
  5. 趋势图（P1）。
- 离线导出：计划报告需支持 CLI 离线导出（现有离线渲染只处理任务报告），否则 CLI 报告列表中的计划报告无法导出。

### 7.15 任务列表「加入计划」（FR-15）

- 定时任务列表增加行操作/批量操作「加入计划」；
- 弹窗选择目标计划，将选中任务按顺序追加到计划末尾；
- 已存在于该计划的任务自动跳过并提示；
- 该入口不改变计划原有调度与执行策略。

### 7.16 权限（FR-16）

- 新增菜单与页面权限：查询、新建、编辑、删除、导出；
- 计划运行/停止/复制等操作随页面权限；
- 计划报告页权限；
- 在「角色管理」中分配给对应角色；
- 菜单与权限种子以 `INSERT` 形式追加到 `mgmt/sql/update.sql`（不修改已定型的 `init_all_*.sql`）；权限项参照 `test_case` 的写法，菜单 id、权限 id 需避开现有最大值。

### 7.17 多语种（FR-17）

- 菜单中英文：测试计划 / Test Plan；
- 页面字段、状态、提示、错误信息均通过 `biz.T()` 输出；
- 新增 key 同步写入 `zh-CN.json`、`en-US.json` 与菜单翻译文件。

### 7.18 执行记录与互斥（FR-18）

- 每次触发产生一条计划执行记录与 N 条步骤执行记录；
- 同一计划同一时间只允许一轮执行：页面提示、cron 跳过、CLI 返回错误；
- 服务重启时，将遗留的 `running` 执行记录标记为 `stopped`，避免状态悬挂。

### 7.19 计划级产品覆盖（FR-19）

- 计划表单新增「产品配置」，支持选择一个或多个产品（存 `product_list`，逗号分隔）；
- **优先级：计划级 > 任务级**。计划配置了产品时，本轮所有步骤按计划产品执行，任务报告中的关联产品也同步为计划产品；
- 计划未配置产品时，沿用各步骤任务自身的 `product_list`，保持原有行为；
- 计划列表「关联产品」展示计划级产品；计划未配置时展示步骤任务的产品并集；
- 计划执行开始时按"本轮实际使用的产品"做鉴权刷新，避免刷新了未使用的产品（本期仅保留调用点与空实现，待鉴权刷新方案落地后生效）；
- 计划配置的产品必须存在且去重；**`data` 类型步骤只使用第一个产品**（现有 data 执行链路按单产品精确匹配取环境配置，多产品仅对 `scene` 步骤完整生效）。

### 7.20 计划导出（FR-20）

- 计划列表支持单条导出与批量导出；
- 导出内容为可重新导入的单一归档包，包含：
  1. 计划基本信息、调度配置、执行方式、失败策略、计划级产品及步骤顺序；
  2. 步骤引用的完整定时任务定义；
  3. 任务依赖的场景、数据文件、产品配置、环境配置、断言模板、系统参数及上传附件；
- 导出前校验依赖闭包完整性；任务、场景、数据文件等关键依赖缺失时终止导出并列出缺失项；
- 包内使用稳定业务标识（计划名、任务名、场景名、数据文件名）表达关联，不依赖源环境数据库 ID；
- 导出结果应确定性排序，便于版本比较与重复导入验证。

### 7.21 计划导入（FR-21）

- 采用“上传检查 → 冲突处理 → 确认导入”的两阶段流程，支持 `skip`、`overwrite`、`cancel`；
- 检查阶段展示计划、任务、场景、数据、产品及其他依赖的新增项、同名冲突、缺失项和关联映射结果；
- 确认阶段在事务中按“基础依赖 → 数据/场景 → 任务 → 计划及步骤”的顺序落库，并把步骤任务名映射为目标环境 `schedule.id`；
- `skip` 表示复用目标环境同名对象，仍须保留计划与该对象的关联；`overwrite` 表示更新同名对象；`cancel` 不落库；
- 任一步骤任务无法导入或映射时，该计划整体不落库，并明确返回缺失任务；
- 同一导入包内多个计划互相独立：单个计划失败不影响其他依赖完整的计划，但共享依赖的写入必须保持一致；
- 导入为异步耗时操作，确认接口立即返回导入任务标识，页面可查询最终结果（现有任务导入为 fire-and-forget、无状态接口，此为**新增能力**，需持久化导入任务状态并支持页面轮询）；
- 导入不得执行包内 SQL 或脚本；归档解包需防止路径穿越，附件和数据文件仅写入平台规定目录。

## 8. 状态定义

### 8.1 计划状态（`plan_status`）

| 状态 | 含义 |
|---|---|
| not_started | 未开始（新建/复制） |
| running | 调度已启用（不代表正在执行） |
| stopped | 已停止调度 |
| finished | 一次性计划执行完成（once） |

### 8.2 计划执行状态（`test_plan_run.status`）

| 状态 | 含义 |
|---|---|
| running | 本轮执行中 |
| finished | 全部步骤成功 |
| failed | 存在失败步骤，或前置校验失败 |
| stopped | 被用户停止 |

### 8.3 步骤执行状态（`test_plan_step_run.status`）

`not_started` / `running` / `success` / `fail` / `skipped` / `stopped`

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 兼容性 | 不改变现有任务、报告、cron 行为；未使用计划的环境零影响 |
| 并发安全 | 同计划互斥执行；并发步骤独立写记录，无数据竞争 |
| 性能 | 计划报告聚合为纯查询，单次聚合 ≤ 2 秒（100 步以内）；并发上限可配置 |
| 可靠性 | 执行记录完整落库；服务重启自动恢复 cron 计划；异常不导致进程退出 |
| 可观测性 | 关键节点写 `biz.Logger`；步骤错误信息落库并展示 |
| 安全 | 页面操作受 RBAC 控制；CLI 使用 JWT；导入包限制类型与大小，防止路径穿越，不执行包内 SQL/脚本；计划不额外存储敏感信息 |
| 数据保留 | 执行记录默认长期保留；后续支持按计划保留最近 N 次（`planRunHistoryKeep`） |
| 可用性 | 列表/表单交互与定时任务一致，降低学习成本 |

## 10. 验收标准

| 编号 | 验收项 | 预期结果 |
|---|---|---|
| AC-01 | 新建计划（3 个步骤） | 列表展示步骤数 3，详情按顺序展示任务 |
| AC-02 | 计划名重复 / 任务不存在 / 无步骤 | 保存失败并给出明确提示 |
| AC-03 | 串行 + 失败即停，第 2 步失败 | 第 3 步为跳过，计划 failed，报告可见 |
| AC-04 | 串行 + 失败继续 | 全部步骤执行，计划 failed，步骤结果齐全 |
| AC-05 | 并发 + 失败即停（并发上限 2） | 排队步骤被跳过，已启动步骤执行完成 |
| AC-06 | cron 计划运行 | 状态 running，next_at 正确，到点触发；重启后仍生效 |
| AC-07 | 立即执行 | 产生 manual 记录，计划调度状态与 next_at 不变 |
| AC-08 | 停止运行中的串行计划 | 后续步骤 skipped，计划 stopped，cron 被取消 |
| AC-09 | 同一计划并发触发两次 | 仅一轮执行，另一次提示"计划正在执行" |
| AC-10 | CLI 触发并轮询 | 状态与页面一致，可获取报告地址 |
| AC-11 | 计划报告下钻 | 点击步骤可进入对应任务本次报告 |
| AC-12 | 任务列表「加入计划」 | 选中任务追加到计划末尾，重复任务被跳过 |
| AC-13 | 权限与 i18n | 无权限角色不可访问；中英文切换正常 |
| AC-14 | 计划级产品覆盖 | 计划配置产品 A、步骤任务配置产品 B，执行请求发往 A，任务报告关联产品为 A |
| AC-15 | 计划产品回退 | 计划未配置产品时，步骤按各任务自身产品执行 |
| AC-16 | 报告统一列表 | 计划执行完成后，「结果报告列表」出现类型为"计划"的报告，可筛选并打开下钻 |
| AC-17 | 存量回归 | 既有任务执行、报告、调度行为不变 |
| AC-18 | 单条/批量导出 | 生成一个计划归档包，包含所选计划、步骤任务及完整依赖，且关联不依赖源环境数据库 ID |
| AC-19 | 导入检查 | 上传归档包后展示计划、任务、场景、数据、产品等对象的新增、冲突、缺失及映射结果，不直接落库 |
| AC-20 | 跳过冲突导入 | 复用目标环境同名对象并保留全部关联，完整计划成功落库 |
| AC-21 | 覆盖冲突导入 | 同名对象按包内容更新，步骤正确映射到目标环境任务 ID |
| AC-22 | 步骤任务缺失 | 任一步骤任务无法导入或映射时，该计划整体不落库，并返回缺失任务明细 |
| AC-23 | 导入包安全 | 路径穿越、非法文件类型、超限归档或包含脚本执行声明的包被拒绝，且不污染目标目录 |
| AC-24 | 同名计划重建 | 删除计划后可用同一名称重新创建成功 |
| AC-25 | data 步骤单产品 | 计划配置多个产品时，data 类型步骤只使用第一个产品且能正常取到环境配置 |

## 11. 边界与限制

1. 停止计划不能中断已开始的任务执行；
2. 并发步骤共享产品环境时可能互相影响（token、测试数据），需由使用者自行保证任务独立性；
3. 计划配置了产品时，所有步骤统一使用计划产品，步骤任务自身的产品配置在本轮被覆盖；其中 `data` 类型步骤只使用第一个产品；
4. 计划引用的任务被删除后，计划执行前置校验失败，整轮不执行；
5. 计划执行中不允许修改步骤；
6. 计划执行记录不做自动清理（后续增量）；
7. 计划名称唯一索引叠加软删除，删除时需改写名称（追加删除时间戳），否则同名计划无法重建；
8. 计划执行前的统一产品鉴权刷新本期仅提供空实现，多步骤共用产品时仍按各步骤原有逻辑处理。

## 12. 依赖与风险

| 风险/依赖 | 说明 | 应对 |
|---|---|---|
| 依赖任务执行函数改造 | 需要抽取 `RunTaskOnce` 返回执行结果与报告 ID，并支持产品覆盖 | 保留 `RunOnceTask` 兼容包装，减小回归风险 |
| 产品覆盖一致性 | 计划产品覆盖任务产品后，执行、任务报告、鉴权刷新需使用同一套有效产品 | 统一由 `effectiveProductList` 计算，执行与报告共用 |
| 报告列表变更 | `dashboard` 新增计划类型字段与枚举值 | 仅新增字段与代码分支，任务报告逻辑不变 |
| 并发执行资源竞争 | 多任务同时运行可能压垮被测环境 | 并发上限可配、默认 5、页面提示风险 |
| 任务状态语义 | 计划步骤执行若复用任务执行可能改写任务状态 | 步骤执行设置 `UpdateTaskStatus=false` |
| 鉴权刷新方案未落地 | 计划内多步骤可能重复登录，但统一刷新能力当前不存在 | 本期只新增 `PrepareProductAuth` 空实现并保留调用点；真实刷新落地后改为计划开始刷新一次、步骤内跳过 |
| 报告渲染多链路 | 计划报告除 Web 渲染外，还需覆盖 CLI 离线导出与 GoAdmin 详情页 | 在 `pages/report_export.go` 补 `case "plan"`，详情页链接按报告类型分流 |
| cron 重启恢复 | 新增独立调度器 | 启动时加载 running 计划，复用现有 `Crontab` 实现 |
| 导出依赖闭包不完整 | 现有任务导出存在部分引用缺失未被发现、网页导入信息不完整的问题 | 计划导出重新构建并逐项校验依赖闭包，不直接拼接或执行 SQL |
| 同名对象关联丢失 | 现有任务导入按冲突项过滤关联，可能导致跳过/覆盖后任务与场景解除关联 | 检查阶段生成显式名称映射，确认阶段先落依赖再重建全部关联 |
| 导入包安全 | 非法归档可能造成路径穿越、资源耗尽或文件污染 | 限制格式/大小/文件数，安全解包到临时目录，校验后原子迁移 |

## 13. 已确认口径

2026-10-23 首次确认，2026-11-05 补充确认（含后续调整）：

1. **同一任务在一个计划中只允许出现一次**：由 `test_plan_step` 唯一约束 `(plan_id, task_id)` 保证；如需重复执行同一任务，通过复制任务或拆分计划实现。
2. **支持计划级产品覆盖（计划级优先）**：`plan.product_list` 非空时覆盖所有步骤任务的产品，任务报告关联产品同步为计划产品；为空时回退到各任务自身产品。
3. **计划报告并入「结果报告列表」**：报告类型新增枚举"计划"（`report_type=plan`），报告数据存 `dashboard.report_data`，通过 `related_plan_id` / `related_plan_run_id` 关联计划与执行记录，不自建独立报告列表。
4. **计划导入/导出纳入本期**：导出计划、步骤任务及完整依赖；导入采用两阶段检查，支持跳过/覆盖冲突；步骤任务无法映射时该计划整体失败。
5. **执行记录长期保留**：本期不做自动清理；后续如需限制保留条数，通过系统参数 `planRunHistoryKeep` 增量支持。
6. **`data` 步骤只取首个产品**：计划级产品配置仍支持多选，但 data 类型步骤只使用第一个产品，多产品完整生效仅限 scene 步骤。
7. **鉴权刷新本期只落 stub**：新增空实现并保留调用点，真实逻辑待 `auth_refresh_design.md` 落地后接入。
8. **同名计划可重建**：删除计划时改写 `plan_name` 为 `<原名>_deleted_<时间戳>`，规避唯一索引与软删除的冲突。
