#### Console Function Module
Class Postman's visual editing of test data. Supports multiple test data requests at once, executes concurrently by default, and easily achieves concurrent testing.
- Definition domain: Interface definition management
- Running domain: Maintenance of interface dimension running data
- Data domain: Running data maintenance without relying on interface definitions
- Scenario domain: Free combination of interface data, reusable
- Data history domain: View historical execution of run data
- Scenario history domain: View historical execution of run scenarios

#### Management Function Module
Data created in the console can be viewed in the management domain, and documents can also be edited directly through the management domain for rapid writing and management.
- Dashboard: View various statistical data maintained by the system, e.g.: Distribution of interface types, Interface specification checks, Whether interfaces are automated, Recent 6-month execution distribution and trends, Interface statistical data for each application, etc.
- Console: Visualized maintenance of interface test data
- Use cases: Maintenance of use case information, and maintenance of imported use cases through Xmind; supports case statistics reports (test-time trend chart, plan-type data, extension-info dimension statistics and click-through navigation)
- Scenarios: Contains scenario lists and data lists, with scenarios consisting of one or more data
- Results: Record of execution results, including: Data test history, Scenario test history, etc.
- Tasks: Configurable one-time or scheduled task execution scenarios or data, related to different environments to achieve cross-environment reuse of scenarios or data.
- Environments: Maintenance of authentication information, common parameter maintenance, etc., supports product and application dimension statistical reports view; i18n sync supports AI translation
- Files: Data storage is divided into two parts, management data is stored in MySQL, and execution history data is stored on the server, reducing MySQL queries and calls, faster speed, lighter storage; CLI offline run mode uses SQLite storage
- Description: System design and usage documentation
- Logs: Record of page operation logs
- Management: Maintenance of system user permissions

#### Intelligent Testing Assistant Module
- Intelligent cases: Generate test cases from interface definitions or requirement descriptions; cases can be optimized and reused.
- Intelligent data: Generate test data from interface definitions; data can be analyzed, tested, and reused.
- Intelligent scenarios: Generate test scenarios from interface definitions; scenarios can be analyzed, tested, and reused.
- Intelligent analysis: Manage defects and optimization tickets produced from data and scenario execution analysis.
- Intelligent templates: Define various prompt templates.

#### CLI Run Mode
- Runs offline with SQLite, executing data/scenarios without MySQL.
- Invokes interfaces via command line to execute data and scenarios, supporting `--param` command-line placeholder parameter injection.
- The port is read from the configuration file by default; tasks execute in top-to-bottom order.

#### Data Sources
- Test data (automatically generated by the system + manually input)
- Fuzzy data (automatically generated)
- Variable provision (interface results, dependency provided, process variables visible)
